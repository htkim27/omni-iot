# ADR 0001: 로컬 음성 어시스턴트 설계 원칙

## 상태

Accepted

## 배경

`omni-iot` 프로젝트는 Jarvis 스타일의 IoT 어시스턴트를 목표로 하는 로컬 전용 음성 챗봇 하네스입니다. 시스템 구축 초기 단계에서 사용자의 핵심 요구사항과 제약 조건을 명확히 하고, 이를 바탕으로 한 설계 원칙을 문서화할 필요가 있습니다.

## 결정

프로젝트 전반에 걸쳐 다음 원칙과 제약을 따릅니다.

1. **단일 GPU 환경에서의 서빙 (Hardware Constraint)**
   - 시스템은 단일 **RTX 5070 Ti** 환경에서 완벽하게 구동되어야 합니다.
   - 자원 최적화를 위해 무거운 프레임워크 대신 `llama.cpp`를 활용하여 코어 모델을 서빙합니다.

2. **OMNI → TTS 파이프라인 (Not STT → LLM → TTS)**
   - 고전적인 3단계 파이프라인 대신 입력 오디오를 직접 처리하는 **Qwen3-Omni**를 사용합니다.
   - 현재 `llama.cpp` 환경에서 Audio-out을 지원하지 않기 때문에, OMNI 모델이 텍스트를 출력하고 `k2-fsa/OmniVoice`가 음성으로 변환하는 **Audio → OMNI → Text → TTS** 아키텍처를 채택합니다.
   - 모델 제어 지시는 system 메시지에 두고 user 메시지에는 오디오만 넣어, 내부 지시문과 사용자 transcript의 경계를 유지합니다.

3. **실시간 동시 발화(Full-duplex) 및 일상적 대화 지향**
   - ChatGPT의 음성 모드처럼 사용자가 언제든 자연스럽게 말을 끊고 끼어들 수 있는(Barge-in) **동시 발화(Full-duplex)**를 지향합니다.
   - 기계적인 응답이 아닌, 일상적이고 자연스러운 대화(Jarvis 스타일)가 가능하도록 실시간 오디오 하네스를 구축합니다.

4. **로컬 호출어와 명시적 대화 수명주기**
   - 외부 서비스 없이 openWakeWord의 `Hey Jarvis` 모델로 sleep 상태를 해제합니다.
   - 오디오는 16kHz mono Int16 PCM WebSocket stream으로 전달합니다.
   - `sleeping → recording → processing → speaking → follow_up` 상태를 명시적으로 관리하고, 응답 후 제한된 시간 동안만 호출어 없는 후속 대화를 허용합니다.

5. **MCP를 통한 점진적 IoT 확장성**
   - 코어 AI 파이프라인과 IoT 제어 로직을 강하게 결합하지 않습니다.
   - 1단계로 **MCP(Model Context Protocol) 클라이언트**만을 내부에 탑재하며, 추후 다양한 IoT 제어 도구(Tools)를 MCP 서버 형태로 연결하여 제어합니다.

6. **Always-On 분산 입출력 기기 연동**
   - 하네스 구축이 완료된 후, 각 공간(Room)의 디바이스들을 음성 센서로 활용합니다.
   - **방 1**: 안 쓰는 안드로이드 스마트폰 공기계를 Always-on 마이크 겸 스피커로 재활용.
   - **방 2**: 브리츠 블루투스 스피커를 Always-on 입출력 장치로 연결.

7. **모던 파이썬 생태계 (`uv` 기반)**
   - 개발 언어는 Python을 사용하며, 패키지 및 가상환경 관리는 빠르고 결정론적인 빌드를 위해 `uv`를 표준으로 채택합니다.

## 결과

- **장점**: 하드웨어 제약과 AI 파이프라인이 명확해 불필요한 기술 스택 탐색을 줄이고, 핵심 대화 하네스와 향후 MCP/장치 연동을 독립적으로 발전시킬 수 있습니다. 호출어 판단도 실행 중 외부 네트워크에 의존하지 않습니다.
- **비용**: Qwen3-Omni와 OmniVoice를 한 GPU에 함께 올리므로 VRAM 여유와 지연시간을 계속 측정해야 합니다. 브라우저 RMS VAD는 소음·긴 휴지에 민감하고, `ScriptProcessorNode`는 향후 AudioWorklet으로 교체해야 합니다.
- **운영 기준**: 16GB RTX 5070 Ti에서는 20 GPU layers를 보수적 기본값으로 사용합니다. 더 높은 offload 값은 목표 장비에서 peak VRAM과 OOM 여부를 검증한 뒤 적용합니다.

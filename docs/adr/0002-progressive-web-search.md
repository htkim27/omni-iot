# ADR 0002: 작고 반복적인 웹 검색

## 상태

Accepted

## 배경

음성 어시스턴트의 모델 context에는 system prompt, 대화 history, MCP tool catalog와
검색 결과가 함께 들어갑니다. 한 번의 검색에서 많은 결과나 페이지 본문 전체를 가져오면
관련 없는 텍스트가 context를 차지하고, 응답 지연과 API 비용이 늘며, 정작 중요한 근거가
잘릴 수 있습니다. 반대로 검색을 한 번으로 제한하면 초기 검색어가 부정확하거나 결과가
편향됐을 때 충분한 답을 만들기 어렵습니다.

## 결정

Brave Search MCP에는 다음 progressive retrieval 정책을 적용합니다.

1. 기본 allowlist는 snippet 중심의 `brave_web_search`와 `brave_news_search`로 제한합니다.
   페이지 본문을 추출하는 `brave_llm_context`와 이미지, 영상, 장소, 요약 도구는 기본적으로
   노출하지 않습니다.
2. 웹·뉴스 검색 한 번의 `count`는 기본 5건이며 `MCP_BRAVE_SEARCH_MAX_RESULTS`를 넘지
   못합니다. 모델에게 전달하는 tool schema와 실제 MCP 호출 경계 양쪽에서 상한을
   적용합니다.
3. 공식 Brave schema를 그대로 전달하지 않고 `query`, `count`, `freshness`, `country`,
   `search_lang`만 포함한 축약 schema와 설명을 사용합니다. 실제 호출 경계에서도
   이 목록 밖의 모델 인자를 제거해 노출 정책과 실행 정책을 일치시킵니다.
4. `extra_snippets`와 웹 검색의 `summary`는 기본 정책에서 강제로 끕니다. 더 긴 본문이나
   Brave 요약이 필요한 기능은 별도 요구사항과 context 예산을 검토한 뒤 허용합니다.
5. 첫 결과로 근거가 부족하면 결과 수를 크게 늘리지 않고, 검색 의도·핵심어·관점을 바꾼
   후속 검색을 수행합니다. 기존 MCP multi-round 한도 안에서 서로 다른 출처를 확인합니다.
6. 도구 결과당 문자 수 제한과 턴별 round/call 제한은 추가 방어선으로 유지합니다. 검색
   결과가 잘렸다면 같은 대량 요청을 반복하지 않고 더 구체적인 검색어로 범위를 좁힙니다.

## 결과

- **장점**: 한 번의 검색이 차지하는 context와 지연을 예측하기 쉽고, 여러 작은 검색으로
  출처와 관점을 다양화할 수 있습니다.
- **비용**: 복잡한 질문은 API 호출 횟수와 왕복 지연이 늘 수 있습니다. 검색 횟수는 기존
  턴별 MCP 한도의 적용을 받습니다.
- **운영 기준**: 기본값 5를 유지하고, 조정할 때는 실제 tool result 크기, 응답 품질,
  검색 횟수와 latency를 함께 비교합니다. 단순히 더 많은 결과를 얻기 위해 상한을 높이지
  않습니다.

## 검토한 대안

- **페이지 전체를 우선 수집**: 정보량은 많지만 음성 대화용 context와 지연 예산에 맞지 않아
  채택하지 않았습니다.
- **한 번에 큰 결과 집합 요청**: 왕복 횟수는 줄지만 관련 없는 결과와 단일 검색어 편향이
  커져 채택하지 않았습니다.
- **검색을 한 번으로 제한**: 비용은 가장 낮지만 불충분한 검색을 보완할 수 없어 채택하지
  않았습니다.
